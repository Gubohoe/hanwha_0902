# 2. LLM 답변 캐싱하기

## 2.1 LLM 캐싱이란?

LLM은 같은 요청이 반복되어도 기본적으로 모델을 다시 호출하여 답변을 생성한다.

LLM 답변을 캐싱하면 이전에 생성한 결과를 저장해 두었다가 동일한 요청이 들어왔을 때 저장된 결과를 재사용할 수 있다.

```text
사용자 요청
    ↓
캐시에 동일한 요청이 있는가?
    ↓
 ┌── 있음 ──→ 저장된 답변 반환
 │
 └── 없음 ──→ LLM 호출
                 ↓
             답변 생성
                 ↓
             캐시에 저장
                 ↓
             답변 반환
```

---

## 2.2 캐싱을 사용하는 이유

LLM 캐싱을 사용하면 동일한 요청에 대해 모델을 반복 호출하는 것을 줄일 수 있다.

- LLM API 호출 횟수 감소
- 응답 속도 향상
- API 사용 비용 절감
- 반복적인 요청의 효율적인 처리

특히 개발 및 테스트 과정에서 동일한 프롬프트를 반복해서 실행하는 경우 유용하다.

---

## 2.3 InMemoryCache

LangChain에서는 `InMemoryCache`를 사용하여 간단하게 LLM 결과를 메모리에 캐싱할 수 있다.

```python
from langchain_core.caches import InMemoryCache
from langchain_core.globals import set_llm_cache

set_llm_cache(InMemoryCache())
```

`InMemoryCache`는 캐시 데이터를 프로그램의 메모리에 저장한다.

따라서 프로그램이 종료되면 캐시 데이터도 사라진다.

```text
LLM 요청
   ↓
InMemoryCache
   ↓
┌───────────────┐
│ 캐시 데이터   │
│ 메모리에 저장 │
└───────────────┘
```

간단한 개발 및 테스트 환경에서 사용하기 적합하다.

---

## 2.4 캐싱의 기본 흐름

```text
첫 번째 요청
    ↓
캐시 확인
    ↓
캐시 없음
    ↓
LLM 호출
    ↓
답변 생성
    ↓
캐시에 저장
    ↓
사용자에게 반환
```

같은 요청이 다시 들어오면:

```text
두 번째 요청
    ↓
캐시 확인
    ↓
캐시 있음
    ↓
저장된 답변 반환
```

즉, 두 번째 요청에서는 LLM을 다시 호출하지 않고 캐시된 결과를 사용할 수 있다.

# 3. 직렬화와 역직렬화

## 3.1 직렬화(Serialization)란?

직렬화는 메모리에 존재하는 객체나 모델을 저장하거나 전송할 수 있는 형태로 변환하는 과정이다.

```text
객체 / 모델
    ↓
직렬화(Serialization)
    ↓
저장 또는 전송 가능한 데이터
```

Python 객체를 파일 등에 저장하기 위해 변환하는 과정이라고 이해할 수 있다.

---

## 3.2 역직렬화(Deserialization)란?

역직렬화는 직렬화된 데이터를 다시 객체나 모델로 변환하는 과정이다.

```text
저장된 데이터
    ↓
역직렬화(Deserialization)
    ↓
객체 / 모델
```

즉, 직렬화의 반대 과정이다.

---

## 3.3 직렬화와 역직렬화의 관계

```text
             직렬화
객체 / 모델 ─────────→ 저장된 데이터
     ↑                    │
     │                    │
     └──── 역직렬화 ──────┘
```

모델을 저장하고 나중에 다시 사용하려면 다음과 같은 과정이 필요하다.

```text
모델
 ↓
직렬화
 ↓
파일 또는 저장소
 ↓
역직렬화
 ↓
모델 복원
```

# 4. 모델 저장하기

## 4.1 pickle을 이용한 모델 저장

Python에서는 `pickle`을 사용하여 객체를 직렬화하고 파일로 저장할 수 있다.

```python
import pickle

with open("model.pkl", "wb") as f:
    pickle.dump(model, f)
```

### 주요 내용

- `"model.pkl"` : 저장할 파일
- `"wb"` : 바이너리 쓰기 모드
- `pickle.dump()` : 객체를 직렬화하여 파일에 저장

```text
model
  ↓
pickle.dump()
  ↓
model.pkl
```

---

# 5. 모델 로드하기

## 5.1 pickle을 이용한 모델 로드

저장한 모델은 `pickle.load()`를 사용하여 다시 불러올 수 있다.

```python
import pickle

with open("model.pkl", "rb") as f:
    model = pickle.load(f)
```

### 주요 내용

- `"model.pkl"` : 불러올 파일
- `"rb"` : 바이너리 읽기 모드
- `pickle.load()` : 저장된 데이터를 역직렬화

```text
model.pkl
   ↓
pickle.load()
   ↓
복원된 model
```

# 6. 모델 저장과 로드 전체 흐름

```text
[실행 중인 모델]
       │
       │ 직렬화
       ↓
    model.pkl
       │
       │ 역직렬화
       ↓
[복원된 모델]
```

모델을 매번 새롭게 생성하거나 설정하지 않고 저장해 두었다가 필요할 때 다시 로드할 수 있다.

# 7. 직렬화와 LLM 모델

LLM 애플리케이션에서도 모델이나 관련 객체를 저장하고 다시 불러와야 하는 상황이 발생할 수 있다.

예를 들어 애플리케이션에서 사용하는 객체를 저장해 두면 프로그램을 다시 실행했을 때 저장된 데이터를 이용할 수 있다.

다만 LLM 자체의 대형 가중치 모델을 단순히 `pickle` 하나로 저장하고 사용하는 것과 일반 Python 객체를 저장하는 것은 구분해서 이해해야 한다.

```text
일반 Python 객체
    ↓
pickle 등으로 직렬화
    ↓
파일 저장
    ↓
역직렬화
    ↓
객체 복원
```

대형 AI 모델은 사용하는 프레임워크와 모델 형식에 따라 별도의 저장 및 로드 방법을 사용하는 경우가 많다.

---

# 8. 캐싱과 모델 저장의 차이

LLM 캐싱과 모델 저장은 목적이 다르다.

| 구분 | LLM 답변 캐싱 | 모델 저장 |
|---|---|---|
| 목적 | 이전 답변 재사용 | 모델/객체 보존 |
| 저장 대상 | LLM 요청과 결과 | 모델 또는 객체 |
| 주요 효과 | 호출 감소, 속도 향상 | 모델 재사용 |
| 예시 | `InMemoryCache` | `pickle` |
| 핵심 개념 | 캐시 | 직렬화/역직렬화 |

### LLM 캐싱

```text
요청
 ↓
캐시 확인
 ↓
기존 답변 재사용
```

### 모델 저장

```text
모델
 ↓
직렬화
 ↓
파일 저장
 ↓
역직렬화
 ↓
모델 복원
```

# ⭐ 오늘의 핵심

- LLM 답변 캐싱은 동일한 요청에 대해 기존 결과를 재사용하는 방법이다.
- 캐싱을 사용하면 LLM API 호출 횟수와 비용을 줄이고 응답 속도를 높일 수 있다.
- `InMemoryCache`는 캐시 데이터를 메모리에 저장한다.
- 직렬화(Serialization)는 객체나 모델을 저장 또는 전송 가능한 형태로 변환하는 과정이다.
- 역직렬화(Deserialization)는 저장된 데이터를 다시 객체나 모델로 복원하는 과정이다.
- Python에서는 `pickle.dump()`를 이용해 객체를 저장할 수 있다.
- `pickle.load()`를 이용해 저장된 객체를 다시 불러올 수 있다.
- **캐싱은 결과를 재사용하기 위한 것이고, 직렬화는 객체나 모델을 저장하고 복원하기 위한 것**이다.
